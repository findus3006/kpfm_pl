# New
## New features
- Another decoding method should be supported. That is TTTR2. Read: https://github.com/PicoQuant/PicoQuant-Time-Tagged-File-Format-Demos/blob/master/PTU/Python/Read_PTU.py and write a method that for this. Its supposed to work with a Multiharp (laser signal is channel 0, APD 1 and 2 are channels 1 and 2 respectively) and a Picoharp (No laser channel. APD 1 and 2 are channels 1 and 2 respectively). When loading the ptu, the header will provide the information for the decoding method to be determined.

# Added in the past
## New features:
- [x] (v1.8.0) **Fitted background and bins before the rise in the tail fit** (both off by default). `PTU.fit_lifetime(fit_background=True)` fits the constant offset instead of fixing it at the dark counts (`background` ± `background_err`, one more parameter in the BIC); `fitting.MultiExpFit(fit_offset=True)`, `offset_value()`. `prerise=True, prerise_gap=2.0` also fits the bins more than `prerise_gap` ns before the histogram maximum: they hold the tail of the previous laser pulse and enter the fit at `t + T` (`t_model`, `prerise_points`), which extends the observed decay to the whole laser period (new helper `utils.prerise_mask`). `prerise` leaves out lifetime bins that are not fully inside the period (also bins that never fill in a file whose header period is too long); `fit_background` alone keeps the bins of the plain tail fit, so their BIC stays comparable. `lifetime_trace`/`flid` take `prerise=`/`prerise_gap=`, and `background_rate=` now also sets the offset of the per-bin tail fits (never fitted per bin). New warning with a fitted background (tail fit and IRF fit): a lifetime above `period_fraction`=50 % of the laser period is barely separable from the background. GUI: *fit background B* works without an IRF; *Before the rise: also fit these bins* + *Gap before maximum* in the lifetime fit and the FLID fit window (copied by *Copy fit window*); hatched region, curve drawn on both sides of the rise, table row *Bins before the rise*; lifetime trace/FLIDs reuse the background of the last lifetime fit, otherwise dark counts + log warning; the warning threshold is in *Advanced fit settings*. On `ptu_test1` (2 exp, MLE): fixed dark offset 6.1 / 29.2 ns, fitted background 10.8 ± 0.3 counts/bin and 2.5 / 14.1 ns.
- [x] (v1.7.0) **IRF reconvolution**: `fitting.IRFReconvolutionFit` (periodic FFT convolution of the bin-integrated exponential kernel with the background-subtracted, unit-area, Fourier-shifted IRF; fitted shift δ, optional background B and scatter s; least squares or Poisson MLE; analytic Jacobian) plus `prepare_irf`, `exp_kernel`, `irf_fwhm`. `PTU.fit_lifetime(irf=PTU|Signal|array, fit_background=, fit_scatter=, irf_shift=)` fits the whole period (manual mode: start…end), `PTU.irf_histogram` checks resolution/period, the window must cover a whole period. `lifetime_trace`/`flid` take `irf=`, `irf_shift=`, `background_rate=`, `scatter_fraction=`. The *Incomplete decay* toggle switches periodic/single-pulse kernel. GUI: *Choose IRF file…* (remembered across sessions), *use IRF*, *fit background B*, *fit scatter s*; table rows IRF shift δ, IRF FWHM, scatter; shifted IRF in the plot; lifetime trace/FLIDs reuse δ/B/s of the last lifetime fit, otherwise tail fit + log warning. Literature and explanation: `docs/irf_reconvolution.md` (in the repository since v1.7.2, linked from `docs/ptu.md` and `docs/gui.md`) and `docs/ptu.md#irf-reconvolution`. Note: the test data contain no IRF recording; verified on synthetic data (kernel vs. brute-force integration, unbiased recovery of τ, δ, B, s).
- [x] (v1.6.0) **Fractions and mean lifetimes in the backend**: `fitting.amplitude_fractions`, `intensity_fractions`, `mean_lifetime(A, tau, kind)` (row-wise too); `MultiExpFit.fractions()`/`mean_lifetime()` with propagated errors; fit results gain `f_amp`/`f_int` (± errors), `tau_amp` (± error, `tau_amp_fit`). `fit_warnings` uses `intensity_fractions`.
- [x] (v1.6.0) **Mean lifetime choice** (`mean_lifetime="intensity"|"amplitude"` for `fit_lifetime` → `tau_mean`, `lifetime_trace`, `flid`). GUI: *Advanced fit settings → Mean lifetime* (τ_int = Σaτ²/Σaτ or τ_amp = Σaτ/Σa) for the fit table/title, the lifetime trace and the FLID maps.
- [x] (v1.6.0) **Incomplete-decay correction is a toggle**: `decay_correction=True/False` for `fit_lifetime`, `lifetime_trace`, `flid`; GUI: *Advanced fit settings → Incomplete decay* (default on; off hides the *A (fitted)* rows).
- [x] (v1.6.0) **Fit table**: per component τ ± error, *A (%)* = Aᵢ/ΣA and *I (%)* = Aᵢτᵢ/ΣAτ with errors, *A (counts)*; *Normalise* ("scale histogram to 1") removed from the GUI — the lifetime fit always works on raw counts (the backend keeps `normalize=`). The *sum(A) ≤ 1* constraint therefore only acts on the per-bin fits.
- [x] (v1.5.0) **BIC** of every lifetime fit (`quality["bic"]` = χ² + k·ln n, Poisson deviance for the MLE; new `bic_from` option and `deviance`/`n_points`/`n_params` in `poisson_chi_squared`). GUI: ΔBIC against the previous *Fit* click if it used the same histogram, window and weighting, in the fit table, a coloured line above the plot title and the log — green better, red worse (overfitting), gray about the same or "not comparable". The |ΔBIC| threshold (default 10, Kass & Raftery) is in *Advanced fit settings → Model selection*. Not for the lifetime trace/FLID.
- [x] (v1.5.0) **Over-fitting warnings** (`fitting.fit_warnings`, `MultiExpFit.diagnostics()`, `fit_lifetime(...)["warnings"]`, thresholds via `diagnostics=`): amplitude compatible with zero (< 2 σ) or < 1 % of the intensity, two lifetimes merged (< 2 combined σ or < 10 %), parameter within 1 % of a bound. Logged as warnings; thresholds configurable in *Advanced fit settings*.
- [x] (v1.5.0) **Incomplete-decay correction**: with periodic excitation the fitted amplitudes include the tails of earlier pulses, `A_fit = A / (1 − exp(−T/τ))`; the lifetimes are unaffected. `MultiExpFit(period=...)` reports per-pulse `A` (errors propagated, `corrected_covariance()`) and `tau_int` from them, the fitted values stay as `A_fit`/`A_fit_err`/`tau_int_fit`. Always applied by `fit_lifetime`, `lifetime_trace` and `flid` (`meta["amplitudes_fit"]`). GUI table: *A1…* per pulse, *A1 (fitted)…* of the curve; lifetime-trace CSV gets `A{i}_fit` columns.
- [x] (v1.5.0) **Poisson maximum likelihood**: `weighting="mle"` (`MultiExpFit(statistic="poisson_mle", count_scale=...)`, iteratively reweighted least squares, converges to the MLE; works with *Normalise*). On `ptu_test1` the Neyman-weighted fit underestimates the long lifetime (simulated: 28.6 ns instead of 30.2 ns), the MLE does not (30.3 ns). New `poisson_deviance`. GUI: *Weighting → Poisson MLE*.
- [x] (v1.4.0) New **AFM shift** tab: up to 4 `.jpk` files, one row per file and one column per channel (channels common to all files). The circle is drawn on the reference file's *Draw on* channel and copied to the same scan position on every other file; *Show the circle also on* picks the channels with dashed copies, a blue dotted circle marks the reference position. Manual shift: drag each file's circle onto the feature → dx/dy/|d| table. Automatic shift: new backend helper `utils.image_shift` (FFT cross-correlation, sub-pixel, correlation coefficient as quality), on the whole image or a window around the circle; *Move circles to detected shift*. Circle statistics per file, CSV export (shifts + statistics) and figure metadata with all sources.
- [x] Count check for the bins passed into `flid()`: at least `min_counts` (default 100) photons in `coverage` (default 90 %, 50 % = median) of the bins, otherwise a warning with the suggested bin time per ROI/FLID. `auto_bintime=True` recomputes with that bin time (ROI count range scaled along). Also in `lifetime_trace()`/`arrival_time_trace()`. GUI: *Photons per time bin* in the FLID group, advice per ROI in the log, *Bin time: automatic (per ROI)* with the counts axis scaled per map.
- [x] FLIDs without fitting: `PTU.arrival_time_trace()` (mean photon arrival time per bin, dark counts subtracted, optional correction of the finite window) and `flid(method="mean_arrival")`. GUI: *Lifetime from* = Fit / Mean arrival time / Both (side by side on identical bins). Dark counts do matter (flat background pulls the mean towards T/2), so they are subtracted. Note: on the test file the 1-exp fit gives shorter lifetimes than the mean arrival time because the decay is multi-exponential (χ²ᵣ 4.1 for 1 exp vs. 1.06 for 2 exp).
- [x] The lifetime fit returns `tau_int` ± `tau_int_err` (intensity-weighted mean lifetime, error from the fit covariance; also `A_err`/`tau_err`), shown in the fit table and plot title.
- [x] FLIDs in the GUI are square; double-click a map (or *Pop out map(s)*) opens it in its own window with zoom/pan and colour min/max, colormap and lin/log.
- [x] Advanced fit settings: *Constraint* (`sum(A) ≤ 1`). It is only applied to normalised fits — the lifetime trace and FLID per-bin fits, and the lifetime fit with *Normalise* ticked — so raw-count fits are unaffected (there the constraint would cap the amplitudes at 1 count). Unset amplitude bounds follow the constraint (`A ≤ 1`).

## Bugs:
- [x] (v1.8.2) **Seam bins are detected once and left out of every lifetime fit.** Seam bins are lifetime bins that are not fully inside one laser period: bins past the period, its partly covered last bin (period 1603.70 bins: about 70 % of the neighbours' counts) and bins that never fill (legacy files whose header period is too long); they follow a lifetime shift. Before, the handling differed per fit: the unshifted tail fit kept all of them, the bins before the rise left them out without showing it, the IRF fit left out and showed one, and a shifted tail fit left out one bin even when several were empty (`ptu_test1`: four empty bins fitted as zeros inside the decay). Now `PTU.seam_bins()` is the single detection (geometry, not count statistics) and `fit_lifetime`, `lifetime_trace`, `arrival_time_trace` and `flid` take `exclude_seam=True` (tail fit, bins before the rise, IRF and per-bin fits; with `bins > 1` the whole group). Fit results list them: `excluded_ns`, `seam_points`, `seam_ns`. GUI: tickbox *Seam bins: leave out (auto-detected)*, on by default, in the lifetime fit and the FLID fit window (copied by *Copy fit window*); the fit plot marks all of them in grey, the table has the row *Seam bins (not fitted)*. Results move slightly: unshifted tail fits lose one or a few bins. Answers to the questions: the lifetime shift rotates the data by whole bins (wrapped bins sit up to one bin late, 19 ps on `ptu_test2`), the bins before the rise keep the data and use the model time `t + T` with the exact period; see `docs/ptu.md` (*Seam bins*, *Lifetime shift or bins before the rise?*).
- [x] (v1.8.1) Tail-fit window start: `mode="fraction"` started where the smoothed **rising** edge first reached `fraction` of the maximum, i.e. before the peak, so the fit included IRF-shaped bins of the rise; `mode="inflection"` could likewise pick the inflection of the rising edge (and fell back to the first bin). Both now start **after the maximum**: `fraction` at the first bin where the smoothed decay has fallen to `fraction` of the maximum (`utils.left_bound_fraction`), `inflection` at the dominant inflection of the falling edge (`utils.inflection_left_bound`), falling back to the maximum. `t = 0` stays at the histogram maximum. Affects `fit_lifetime`, `lifetime_trace`, `flid` and `arrival_time_trace`; GUI label *Falling edge (fraction)*. On the three sample files (2 exp, MLE) the start moves from −0.32…0 ns to +0.26…1.34 ns, χ²ᵣ drops in every case (e.g. `ptu_test2` inflection 3.20 → 1.38) and τ_int rises by 0.1–0.6 ns (≤ 3 %).
- [x] (v1.8.1) Lifetime trace / FLID per-bin tail fits with `bins > 1`: a lifetime group that straddled the window start was kept, adding rising-edge bins at the group's mean time, which lengthened the fitted lifetimes regardless of the photon number. Only groups whose bins all lie in the window are fitted now.
- [x] (v1.8.1) Docs: FLID map smoothing (`sigma`) adds its width to the shot-noise spread of the per-bin lifetimes (`docs/ptu.md`, `flid` docstring, GUI tooltip, `docs/gui.md`); use `sigma=0` before judging the width of a map. Also corrected: the mean arrival time equals the fits' `tau_int` "wherever the window starts" only for one exponential; for several it is the `tau_int` of the decay at the window start (longer, since the short components have faded) (`docs/ptu.md`, `arrival_time_trace` docstring).
- [x] (v1.7.2) IRF reconvolution: `prepare_irf` clipped the background-subtracted IRF at zero, which keeps only the positive half of the floor noise; the convolution turned that residue into a flat level taken from the fitted background `B` (−4 % on a synthetic test file, −90 % with a noisier IRF floor; τ, fractions and δ were unaffected, but with `B` fixed from the dark counts the residue would bias the fit). The floor is no longer clipped and is estimated as the mean of the floor bins (median + 5 √median cut) instead of the biased median.
- [x] (v1.7.1) Lifetime trace / FLID per-bin tail fits: the dark-count offset was divided by the row maximum but the fitted data by the maximum inside the fit window, so whenever the window excludes the peak (e.g. manual start after the maximum) the offset was too small by that ratio. It is now in the units of the fitted data.
- [x] (v1.4.0) AFM tab: *Save figure* suggests `<file>_channels` (metadata lists all plotted channels) instead of the first channel's name.
- [x] (v1.4.0) AFM tab: *Export data (CSV)* writes every plotted channel, one file each (`<name>_<channel>.csv`); the *Channel for CSV* drop-down is gone.
- [x] Changing the map smoothing or the FLID axes no longer refits: `flid()` is now `lifetime_trace()` + the new `flid_map()`, and the GUI redraws the maps instantly from the stored per-bin lifetimes.
- [x] Fit progress counts the actual time bins of all ROIs instead of a fixed x/1000 per ROI.
- [x] The FLID has its own fit window (fit start, edge fraction, edge smoothing, start/end) plus *Copy fit window from 'Lifetime fit'*; the note explains that *Region* selects the time bins and the fit window the part of each decay.
- [x] ROI handles have a fixed size on screen (square, kept on zoom/pan/resize); whole box edges can be dragged and the cursor shows the action.
